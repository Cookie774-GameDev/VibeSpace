# Plugin authorization audit — 2026-10-04

## Scope and meaning

This inventory is generated from the 112 entries in `PLUGIN_CATALOG` at base `649ed2f4`. It distinguishes **provider capability** from **VibeSpace implementation**. A link to a credential page is not an OAuth flow. “Manual credential” means the catalog has fields and a bounded provider or trusted-runtime check; it does not mean VibeSpace can create a provider account or grant. “Hosted MCP” means a separate OpenCode remote-server configuration and OAuth lifecycle, not a connected catalog API plugin. Browser login is complete only after OpenCode reports `connected`; neither opening a page nor adding a server proves authorization.

The generated compatibility metadata may use labels such as `official_one_click`; those labels are planning metadata and every catalog entry currently has `oneClickReady: false`. This matrix uses implemented connection behavior. A read-only reachability check found 91 unique catalog documentation URLs, 90 responsive HEAD requests, four definitive 404 responses, and five inconclusive responses or transport failures. The four 404 links were replaced with current official pages for Zapier, Intercom, Square, and Mailgun; all four replacements returned HTTP 200 by GET. Reachability alone does not prove an OAuth flow.

## Verified shared authorization families

- **GitHub**: The [official device flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps) permits a registered OAuth app to issue a device/user code and exchange it after consent. The shipped public client ID returned a valid device authorization response on 2026-10-04. This probe did not approve an account, exchange a token, or prove token longevity. VibeSpace's account probe is `GET /user` and its token is held in its desktop credential runtime. Token expiration settings of the provider registration remain unknown.
- **Google Workspace**: [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app) supports PKCE and desktop loopback redirect, subject to each API's scopes and consent requirements. VibeSpace has no registered client/callback for these catalog entries. Gmail and Drive only have a bring-your-own refresh grant fallback; the other ten Google entries are blocked in this connector.
- **Microsoft 365**: [Microsoft identity](https://learn.microsoft.com/en-us/graph/sdks/choose-authentication-providers) supports public clients with auth code and PKCE or device code, but still requires a registered client ID and scopes. VibeSpace does not implement that grant/callback for the twelve catalog entries. Some listed products may need non-Graph service-specific permissions; the catalog's shared Graph link is not evidence of complete API support.
- **Remote MCP**: [Supabase](https://supabase.com/docs/guides/ai-tools/mcp), [Notion](https://developers.notion.com/guides/mcp/get-started-with-mcp), [Linear](https://linear.app/docs/mcp), [Atlassian](https://atlassian.github.io/atlassian-mcp-server/), [Sentry](https://mcp.sentry.dev/), and [Neon](https://neon.com/guides/neon-mcp-server-github-copilot-vs-code) document hosted remote servers with OAuth. VibeSpace delegates discovery, DCR when allowed, PKCE/state, exchange, persistence and refresh to OpenCode's [remote MCP implementation](https://opencode.ai/docs/mcp-servers/). Catalog API connections remain separate. [Figma](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/) restricts new clients to an approval list; [Canva](https://www.canva.dev/docs/apps/mcp/access/) requires a recognized client/redirect; [Asana](https://developers.asana.com/docs/connecting-mcp-clients-to-asanas-v2-server) requires registered client ID/secret/callback and does not offer DCR. Their endpoint definitions are not proof that a VibeSpace client can complete sign-in.
- **Other credential entries**: Their linked official API/credential docs establish the currently supported manual route. The audit does **not** assert that those providers lack OAuth. No exact VibeSpace public client registration, callback, code exchange, refresh, or revoke implementation was found for these catalog connectors. Provider OAuth support beyond the documented route needs connector-specific registration/review and is not advertised as ready.

## Remaining cross-cutting blockers

1. No user-account consent was performed for GitHub or any remote MCP service during this audit. The GitHub start endpoint was probed without saving a code/token. Native provider acceptance is pending an assigned app instance and account consent.
2. OpenCode stores remote MCP grants in its own application data (see [OpenCode MCP documentation](https://opencode.ai/docs/mcp-servers/)); VibeSpace's OS keychain claim applies to catalog API credentials only. The catalog cannot infer MCP connection from the plugin credential store.
3. For Figma/Canva/Asana, provider approval or exact client registration remains an external prerequisite. For Google/Microsoft and other non-MCP OAuth connectors, app registration, scoped consent, callback, exchange, durable storage, refresh and reconnect/revoke are unimplemented.
4. GitHub token lifetime/refresh depends on the OAuth app registration and the granted token. This audit cannot promise a permanent session without an authorized account and expiry configuration.
