# Jarvis voice chat and native delegation handoff

Status: implementation handoff only. Prepared on `integration/UnifiedChungus-final` at `24e38ebc337e80b3eaadef9c06e8daf808dbbc82` while chat/runtime and native app lanes have active peer ownership. No product code or native app was changed for this document. Recheck HEAD, live locks, and the cited code before implementation.

## Intended behavior

1. Opening Jarvis voice follows the saved **Main Agent chat** choice: resume the last voice chat for the selected provider in the current account/workspace/project, or create a new one. The saved default remains **Resume**. A new chat has its own conversation folder and compact references to still-running tasks; closing voice never stops those tasks.
2. A spoken transcript or typed mini-bar turn goes to the selected **Voice Main Agent** once. It acknowledges promptly, then decides whether to answer directly or delegate. A simple question such as “What day is it?” gets a direct answer and selected-voice TTS without a worker. Actual work can use provider-native subagents. Do not launch a worker just because a voice turn arrived.
3. Delegated work has one stable request identity and one native worker operation per distinct request. The Main Agent receives actual launch, progress, terminal, and error receipts. Show the **actual** provider/model/session and a link or control for its task; never label a submitted event as launched. Repeated STT finals and voice reopen must not launch duplicates.
4. Keep Main Agent and Worker provider settings independent: Codex/Codex defaults; one-request voice or typed overrides do not change saved defaults without an explicit save request. When Main and Worker providers differ, use a real session of the selected Worker provider and that provider's native delegation tools. If that cross-provider route cannot be established, report the limit; never silently substitute the Main provider or fabricate a native child.
5. The saved **Worker session** choice is separate from the Main chat choice. Offer **New worker session for each distinct task** (default, current isolation behavior) and **Resume the last worker session for this provider**. Resume keeps the selected provider's native parent session, with bounded context; an in-flight native child is resumed by its recorded task ID. Every distinct request still gets its own task identity. Keep Codex and OpenCode session handles separate, and do not stop old work when creating a new session. Changing Worker session mode never changes Main chat mode or provider defaults.
6. In the existing Voice settings area, allow a restrained **automatic/provider color** display and user controls for provider accents and color intensity. Color reflects the current Main Agent, actual worker provider, and real states such as listening, working, speaking, and error. Keep text/icon/status labels so color is never the only signal. Respect current theme, monochrome/forced colors, and reduced motion. Do not add another voice panel or appearance system.
7. A permitted “on my screen” request captures one image for the delegated task. If capture is denied or fails, continue with the text and briefly say so. A recoverable launch or worker error returns to the Main Agent with structured cause/status so it can try a safe repair or explain the blocker; do not loop or duplicate the task. Keep existing tool/approval boundaries.

1. **Recheck ownership and current behavior.** Read the newly settled chat/runtime commits and exact locks; claim only the voice, settings, store, and any explicitly released chat adapter files needed. Preserve peer changes. Trace the runtime's actual native delegation receipt for both providers, including native session/task IDs and progress/terminal events.
2. **Make Main Agent decision the single entry path.** Reuse the current `jarvis:send` runtime and voice binding. Apply the existing brief voice-only instruction to both direct and delegated replies, preserving safety/tool instructions. The Main Agent either produces an answer or requests native delegation for work. The voice UI does not prelaunch a worker.
3. **Bridge Worker provider and session mode.** Route a delegation request to the selected provider's real parent session; use Codex native agent tools or OpenCode `task`/`task_id` as the provider supports. Record the exact provider/model/session/task ID, launch proof, and terminal result. Separate Main chat Resume/New from provider-scoped Worker New/Resume; bound or summarize resumed context so it does not grow without limit. Carry one screenshot and bounded recent context when present. Reject unavailable routes visibly.
4. **Persist continuity without bloat.** Replace voice-specific child-card assumptions with an adapter over native task receipts. The task index keeps IDs, provider, status, short summary, and original chat link. Closing/reopening voice changes only the mic/UI binding. A late result updates its original conversation and can be surfaced briefly in the active voice chat without replaying histories or relaunching agents.
5. **Add visual controls in existing Voice settings.** Add saved bounded provider accent and intensity values, use actual task/voice state for colors, and expose accessible labels. Preserve current appearance for existing users until they change the setting.
6. **Handle failures through Main Agent.** Return structured STT/capture/launch/worker/TTS failure receipts where a Main Agent session exists. Permit one safe retry only when the failed operation has a confirmed nonlaunch or idempotent identity; otherwise report the uncertainty and let the user decide. Never change saved settings as a repair side effect.

## Regression and native acceptance after implementation

- Unit/component: direct factual question launches **zero** workers and speaks one answer; substantial task launches exactly one provider-native worker; repeated STT finals produce one task; close/reopen preserves the running task and does not block new chat binding; terminal result arrives once.
- Settings: Main provider and Worker provider remain independent; Main Resume is default; Worker mode defaults to New; both provider combinations and one-request override leave saved defaults unchanged; typed mini bar remains off by default and uses the same coordinator.
- Boundaries: a cross-provider request proves the actual Worker provider/session or reports failure; provider unavailable, screenshot denied, launch failure, ambiguous receipt, and worker failure do not claim success. Main Agent gets error context and speaks a brief truthful result. Voice-only prompt reaches the selected Codex and OpenCode runtime; ordinary chat prompts stay unchanged.
- Visuals: provider and task state drive the existing Orb/panel colors; intensity persists; startup is not red without an error; labels remain clear in monochrome/forced colors and reduced motion.
- STT/TTS: selected Free System, Local Whisper, and Deepgram routes are checked as available; selected Jarvis/Friday/system/local/Deepgram output is verified with actual audible speech where configured. Do not claim cloud-provider success without a real configured call.
- Official native Tauri WebView: after an instance is assigned, attest process/profile/CDP identity, then record time to visible panel and first spoken acknowledgment, actual provider/model/task IDs, direct answer, native delegation, reopen continuity, screenshot success/failure, duplicate suppression, selected TTS, and final spoken result.
